# Практическая работа 5
## Боровская В.В. ЭФМО-01-26

ToDo с PostgreSQL, database/sql и драйвером pgx. Модуль: `borovskaya/pr5`.

## Архитектура

HTTP-запрос проходит через chi и middleware в обработчик `internal/task/handler.go`. Обработчик проверяет входные данные и передаёт контекст с тайм-аутом 3 секунды SQL-репозиторию. `internal/task/postgres.go` выполняет параметризованные запросы к PostgreSQL. Данные сохраняются после перезапуска Go.

`db.go` создаёт общий пул, проверяет подключение через PingContext и ограничивает его десятью открытыми и пятью свободными соединениями. Максимальное время жизни соединения — 30 минут. Старый repo.go хранит учебную реализацию в памяти и объявление ErrNotFound; сервер использует PostgresRepo.

## Подключение и запуск

 Создайте базу todo в pgAdmin. В Query Tool этой базы выполните sql/schema.sql. Скопируйте .env.example в .env и задайте DATABASE_URL локально.

```powershell
go mod download
go run .
```

Адрес: http://localhost:8080. 
Маршруты: GET /health, GET и POST /api/tasks, GET/PUT/DELETE /api/tasks/{id} (PUT принимает title и done). 
Фильтры: /api/tasks?done=true и ?done=false. 
Неверный параметр фильтра возвращает 400.

## SQL и ошибки

Create использует INSERT RETURNING, Get и FindByID — SELECT по ID, List — SELECT ORDER BY id, ListDone — WHERE done = $1, Update — UPDATE RETURNING, Delete — DELETE и RowsAffected. QueryRow читает одну строку через Scan; Query возвращает набор строк с Next, Scan, Close и проверкой Err; Exec применяется, когда строки результата не нужны.

Плейсхолдеры отделяют пользовательские значения от SQL-команды. Ошибки входных данных дают 400, отсутствие задачи — 404, внутренние ошибки БД — 500 с подробностями только в журнале. Успешное создание возвращает 201, удаление — 204 без тела.

## Транзакции и демонстрация

```powershell
go run . -seed
```

CreateMany вставляет три примера через одну транзакцию. Commit подтверждает все операции, отложенный Rollback отменяет незавершённую транзакцию при ошибке. После вставки программа выводит список и результат FindByID. Повторный запуск добавляет новые записи.

## Пул и проверки

```powershell
go vet ./...
go test -v ./...
go run . -pool-check
```

Интеграционный тест использует DATABASE_URL, создаёт собственную запись, проверяет кириллицу, обновление, поиск, фильтрацию и удаление. Остальные задачи не удаляются. Без DATABASE_URL тест пропускается.

Режим pool-check сравнивает 1, 5 и 10 соединений: 20 работников выполняют по 5 запросов SELECT pg_sleep(0.05). Вывод содержит общее время и статистику ожидания соединения.
